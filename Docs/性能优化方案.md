# PuzzleEscape 性能优化方案

> 项目：`D:\PuzzleEscape\PuzzleEscape`（Unity 2022.3.62f3c1，Built-in Render Pipeline）
> 导出日期：2026-11-01
> 状态：**仅导出方案，尚未实施任何优化改动**

---

## 1. 结论摘要

当前卡顿的主因是 **渲染 / 阴影 / 灯光 / 缺少批处理与遮挡剔除**，不是玩法脚本本身。

- 场景约 **6,745 个 Renderer**、**7.7M 顶点**、**20.6M 三角面**，编辑器统计约 **10,979 Draw Calls**。
- 书本模型 `Real_book_encyclopedia_set_01` 占 **2,820 个 Renderer / 6.04M 顶点**，是最大的单一项开销。
- 场景中 **0 个 Static 对象、0 个 LODGroup、0 张 Lightmap**，也没有烘焙 Occlusion Culling 数据。
- 119 盏实时灯、全部物体投射并接收阴影；运行时 AA 2x、HDR 开启、逐像素灯 8 盏。
- UI/交互脚本存在每帧字符串分配与每帧射线检测，属于次要但容易修复的问题。

推荐顺序：

1. **方案 A（快速低风险）**：先解决阴影、灯光、AA/HDR、UI/GC，预计改善 20%~35%。
2. **方案 B（推荐核心）**：书本合并/LOD + 环境静态批处理 + 遮挡剔除，目标 Draw Calls 从约 11k 降到 **2k~4k**，这是解决卡顿的关键。
3. **方案 C（彻底）**：在 B 基础上做烘焙光照 / 房间灯光管理 / 移动端画质分级，面向中低端 Android。

## 3. 瓶颈分析

1. **书本 Renderer 数量与顶点过高**
   - 每个 20 册套装仍按 20 个独立书本 Renderer 渲染；
   - 2,820 个 Renderer 全部投射/接收阴影；
   - 6.04M 顶点对小尺寸书本来说非常不经济。

2. **环境物件完全未批处理**
   - 3,638 个 Environment Renderer，只有 72 个唯一 Mesh、94 个材质，理论上可大量合并；
   - 0 个静态对象，因此没有 Static Batching；
   - 0 个 LOD，也没有按距离关闭小物件。

3. **所有 Renderer 都参与阴影**
   - 6,745 个 Renderer 设置 `shadowCastingMode = On` 且 `receiveShadows = true`；
   - 即使只有 2~4 盏灯真正开启阴影，书本和小摆件仍会进入阴影贴图渲染。

4. **119 盏实时灯**
   - 52 盏范围 < 5m 的小灯仍在灯列表与逐像素计算中参与；
   - 66 盏聚光形成大量灯光-物体配对；
   - 5 盏闪烁灯每帧改亮度。

5. **无室内遮挡剔除**
   - 38 个房间、墙体与走廊天然适合 Occlusion Culling；
   - 目前墙后房间只要在视锥内仍会被渲染。

6. **AA / HDR / 阴影距离对移动端不友好**
   - AA 2x、HDR、阴影距离 20 是桌面可用、移动端偏重的组合；
   - 当前只有“光影质量”三档，没有独立的性能/分辨率/AA 画质档。

7. **UI 与交互每帧工作**
   - 单帧开销不大，但会造成周期性 GC 和 Canvas 重建，表现为轻微顿挫。

## 6. 方案 A：快速低风险包

> 不改场景结构、不重新烘焙；只改运行时脚本与画质设置。

### A1. 书本与小物件关闭阴影

**内容**

- 对 `Real_book_encyclopedia_set_01` 下所有 Renderer：
  - `shadowCastingMode = ShadowCastingMode.Off`
  - `receiveShadows = false`
- 对盆栽、花瓶、小摆件、部分装饰同样处理。
- 保留大家具、门、玩家手电筒的阴影。

**涉及位置**

- `Assets/Scripts/Core/MansionRealModels.cs`：按模型类型决定是否投射/接收阴影。
- 也可以在运行时 `Bootstrap` 中一次性遍历书本容器，避免重烘场景。
- 长期建议在烘焙时写入 `MansionLevelBuilder` / `MansionRealBooks`。

**预期**

- 阴影投射者从 2,000+ 降到数百；
- 阴影 Pass 与书本接收阴影的像素成本明显下降。

**风险**

- 低；书本变小后阴影感减弱，但整体观感影响很小。

### A2. 灯光降级

**内容**

- 52 盏范围 < 5m 的小灯设置 `renderMode = LightRenderMode.ForceVertex` 或 `Not Important`。
- 逐像素灯调整：
  - 低画质 / 移动端：8 → 4
  - 中画质：6
  - 高画质：8
- 阴影灯：
  - 低画质：2 → 1
  - 移动端性能挡：0~1
  - 中/高画质维持 2~4 盏
- 阴影距离 20 → 15（低/移动端）。
- 5 盏 `FlickerLight` 改为 10~20Hz，或只改自发光材质而不是每帧改 Light。

**涉及位置**

- `Assets/Scripts/Core/LightingQuality.cs`
- `Assets/Scripts/Core/FlickerLight.cs`

**预期**

- 降低灯光-物体配对、逐像素光照与阴影贴图成本；
- 对画质影响可控，适合作为第一步。

### A3. 相机与画质设置

**内容**

- 移动端 / 低画质：
  - `QualitySettings.antiAliasing = 0`
  - `Camera.allowMSAA = false`
  - `Camera.allowHDR = false`
  - 远裁剪 80 → 65~70
- 桌面保留 2x AA；无 Bloom/后处理时关闭 HDR。
- 新增“性能 / 均衡 / 画质”预设，把 AA、HDR、阴影距离、逐像素灯、帧率统一管理。

**涉及位置**

- `Assets/Scripts/Player/PlayerFactory.cs`
- `Assets/Scripts/Core/LightingQuality.cs`
- `Assets/Scripts/Core/FrameRateSettings.cs`
- `Assets/Scripts/UI/UIRoot.cs`（设置面板）

**预期**

- 尤其对 Android GPU 有效；AA/HDR 关闭可显著降低带宽与填充率。

### A4. CPU / GC 优化

**内容**

- 计时器文本改为每 1 秒更新一次，缓存 `MM:SS` 字符串。
- 交互射线从每帧降到 10Hz，增加交互 LayerMask；提示文本内容不变时不重复设置。
- `PlayerLantern` 的持有状态改为事件/缓存，不再每帧 `Contains`。
- `LightingQuality` 用固定数组代替每次新建 `List`，并在玩家移动一定距离后才刷新阴影灯。
- `WorldItemSpin` 降到 15~20Hz，或距离玩家较远时停更。

**涉及位置**

- `Assets/Scripts/UI/UIRoot.cs`
- `Assets/Scripts/Player/PlayerInteractor.cs`
- `Assets/Scripts/Player/PlayerLantern.cs`
- `Assets/Scripts/Core/LightingQuality.cs`
- `Assets/Scripts/Interaction/WorldItemSpin.cs`

**预期**

- 减少 GC 尖峰与 Canvas 重建；
- 降低主线程小开销，改善“走路时轻微顿挫”。

### 方案 A 验收

- 热点场景帧时间改善 20%~35%；
- 阴影投射者减少 50% 以上；
- 无玩法/交互回归；
- 不改场景文件，可直接回滚脚本。

## 7. 方案 B：推荐核心包

> 需要重新保存/烘焙场景；是解决卡顿的核心。

### B1. 书本合并与 LOD

**现状**

- 141 组 `book_encyclopedia_set_01`，每组 20 册 = 2,820 个 Renderer；
- 6.04M 顶点，占全部顶点的约 78%。

**做法（按优先级）**

1. **按书架 / `BookRun` 合并**
   - 把同一层书架的 20 册合并为 1 个 Mesh，保留书脊/书页两个子网格；
   - 目标 Renderer：2,820 → 100~300。
2. **LOD**
   - LOD0：0~4m，真实书本；
   - LOD1：4~8m，低面数盒体 + 书脊贴图；
   - LOD2：8~15m，单面/广告牌；
   - 超过 15~20m 直接 Cull。
3. **备选：低模替换**
   - 如果合并后顶点仍偏高，直接为远距离书本生成几十顶点的盒体 Mesh，视觉上仍可读。

**涉及位置**

- `Assets/Scripts/Core/MansionRealBooks.cs`
- `Assets/Scripts/Core/MansionRealModels.cs`
- `Assets/Scripts/Core/MansionLevelBuilder.cs`
- 新增编辑器烘焙工具：`Assets/Editor/BookMeshOptimizer.cs`（建议）

**预期**

- 减少 2,000+ Renderer；
- 远距离书本顶点大幅下降；
- 阴影 Pass 同步下降（若同时关闭书本阴影）。

**风险**

- 合并后书本不能再单独移动，但书本本来就是静态装饰，不影响玩法；
- 需要验证书脊/书页材质槽位与法线。

### B2. 环境静态批处理

**内容**

- 将房间墙板、地板、天花板、固定家具、书架、装饰标记为 Static。
- `StaticEditorFlags` 建议：
  - `BatchingStatic`
  - `OccluderStatic`
  - `OccludeeStatic`
- **排除动态对象**：
  - 门 / 抽屉 / 可拾取物 / 灯光 / 玩家 / 电梯门 / 封印大门 / 任何运行时移动的物件。
- 按房间和材质合并小零件：门框、线条、管道、装饰块等。

**涉及位置**

- `MansionLevelBuilder` 的生成流程
- 新增编辑器后处理工具（标记 Static + 合并）
- `Assets/Scenes/Main.unity`

**预期**

- 3,638 个 Environment Renderer 目标降到数百；
- Draw Calls 显著下降；
- 与遮挡剔除协同效果最好。

**风险**

- Static 标记错误的动态物体会导致门/抽屉不动或剔除异常；
- 合并会增加内存，需要测试包体与运行时内存。

### B3. 遮挡剔除（Occlusion Culling）

**内容**

- 墙体、地板、大件家具作为 Occluder；
- 房间内固定物件作为 Occludee；
- 烘焙 Occlusion Culling，覆盖 38 个房间与走廊；
- 相机远裁剪可配合 65~80 使用。

**预期**

- 墙后房间、走廊另一侧物件不再渲染；
- 室内场景通常可减少 30%~60% 可见 Renderer / Draw Call。

**风险**

- 遮挡烘焙耗时；
- 需要检查门洞、楼梯、电梯等动态开口是否出现错误剔除；
- 动态物件不要标记为 Occluder。

### B4. GPU Instancing 与距离剔除

- 对无法合并的重复模型（椅子、花瓶、盆栽、木箱、木桶）统一开启 `enableInstancing`。
- 当前 94 个材质仅 42 个开启 Instancing。
- 小物件按房间/距离禁用 Renderer 或切 LOD。

### B5. 重新烘焙流程

1. 备份 `Assets/Scenes/Main.unity` 与生成材质。
2. 修改生成/后处理脚本。
3. 重新生成场景。
4. 标记 Static（排除动态对象）。
5. 烘焙 Occlusion Culling。
6. 对比 5 个热点场景的截图与 Profiler 数据。
7. 构建 Windows / Android 复测。

### 方案 B 验收

- Draw Calls：约 11k → **2k~4k**
- 可见顶点：约 13M → **2M~4M**
- Shadow Casters：显著下降
- 桌面热点场景稳定 60 FPS；Android 中端稳定 30 FPS
- 门、抽屉、拾取物、电梯、封印大门交互全部正常

## 8. 方案 C：彻底包（C = B + 深度优化）

### C1. 烘焙光照 / 房间灯光管理

**两条路线：**

1. **烘焙 Lightmap + Light Probes**
   - 静态环境使用烘焙光照；
   - 119 盏实时灯改为自发光灯具 + 少量动态灯；
   - 玩家手电筒保留实时聚光；
   - 移动端取消实时阴影。
2. **房间灯光管理（较轻量）**
   - 只启用玩家所在房间 + 相邻房间的灯；
   - 远处灯关闭或切 Vertex；
   - 可保留实时观感，但需要房间分组与过渡，避免灯光突然跳变。

**预期**

- 灯光/阴影 CPU 与 GPU 大幅下降；
- 是移动端稳定高帧率的关键。

**风险**

- Lightmap 需要 UV2、烘焙时间与视觉重调；
- 房间灯光管理可能出现灯光闪烁/漏光，需要逐房间验收。

### C2. 移动端画质分级

建议新增独立预设：

| 挡位 | AA | HDR | 逐像素灯 | 阴影灯 | 阴影距离 | 帧率 |
| --- | --- | --- | --- | --- | --- | --- |
| 性能 | 0 | 关 | 4 | 0~1 | 15 | 30/60 |
| 均衡 | 0~2 | 关 | 6 | 2 | 20 | 60 |
| 画质 | 2 | 开 | 8 | 4 | 30 | 60 |

配合书本 LOD、小物件 Cull、纹理质量/流式加载。

### C3. 可选：渲染缩放 / 纹理优化

- 内置管线没有 SRP 的动态分辨率，若需要可让相机渲染到较低分辨率 RenderTexture 再上屏；成本与 UI 适配需要评估。
- 检查 Poly Haven 纹理尺寸与压缩格式，开启 Mipmap / Texture Streaming，降低移动端带宽。
- 对远处小物件降低纹理质量。

### C4. 其他备选优化

- 房间级对象激活/卸载（只保留当前与相邻房间），收益大但需要处理任务状态、灯光与门。
- 小物件 Shader 简化（Standard → 更轻的 Lit Shader），但会影响 94 个材质与 Instancing，需单独评估。
- 书本完全替换为低模/贴图册组，进一步降低顶点；视觉需要确认。
- UI Canvas 拆分：静态 HUD 与动态计时/提示分 Canvas，减少重建范围。
- 交互/物理 LayerMask 与 Collider 精简（当前 616 个 Collider，不是首要瓶颈）。

## 10. 验收标准

### 性能

- 桌面 1080p：热点场景 p95 < 16.6ms
- 中端 Android：稳定 30 FPS；高端目标 60 FPS
- Draw Calls 目标 < 4,000
- 可见三角面目标 < 4M
- 每帧 GC Alloc < 1KB
- 无固定周期性卡顿（GC / Canvas 重建）

### 功能与画面

- 门、抽屉、拾取物、电梯、封印大门交互正常
- 灯光、阴影、雾效无明显穿帮
- 书本近景视觉可接受
- 遮挡剔除无错误剔除、无穿墙漏景
- Windows / Android 构建 0 errors / 0 warnings

### 对比方式

- 同一位置、同一朝向、同一画质，截取 5 个热点场景截图
- 用 Profiler / Frame Debugger 记录优化前后数据

## 11. 风险与回滚

- **先备份**：`Assets/Scenes/Main.unity`、`Assets/Art/Materials/Generated`、相关模型材质。
- 方案 A 只改脚本/设置，可单独回滚。
- 方案 B 会修改场景与静态标记，建议先复制一份场景或使用版本控制。
- Static 标记必须排除动态对象，否则门、抽屉、拾取物可能异常。
- Occlusion Culling 烘焙后需逐房间检查门洞、楼梯、电梯开口。
- 烘焙光照属于高风险高收益项，建议在 A/B 稳定后再做。
- 静态批处理与合并会增加运行时内存，需要在 Android 真机上检查内存峰值。
